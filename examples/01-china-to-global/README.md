# 案例 1｜国内从业者进入海外市场

> Synthetic persona · 合成人设，非真实个人资料

## Persona

林玮，30 岁，杭州消费品牌电商运营，4 年经验。希望申请新加坡的 `Regional Marketing Operations`、`E-commerce Operations` 或 `Growth Marketing` 岗位。

## Before｜原始表达

> 负责东南亚店铺日常运营，跟进大促活动和达人合作；整理销售数据，协助团队优化页面和活动效果。

问题不在于这句话“太普通”，而在于它没有说明林玮处理了什么复杂度、做过哪些判断，也无法区分负责、协作和参与。

## After｜Capability Blocks

### 积木 A｜跨市场用户信号转译（Cross-market Insight Translation）

**核心能力**：把分散在客服、经销商和退款记录中的市场反馈归类，识别地区性理解偏差，并转成页面内容与 FAQ 调整建议。

**适配岗位**：Regional Marketing Operations、Localization Specialist

**可迁移价值**：帮助跨区域团队把本地用户信号转成可执行的市场内容决策。

**证据链**：三个市场反复出现产品使用误解 → 汇总六个反馈来源并按问题类型归类 → 推动更新 FAQ 与落地页说明 → 与“使用方式不符”相关的退款原因占比下降 **18%**。

### 积木 B｜多市场活动交付编排（Multi-market Delivery Coordination）

**核心能力**：在素材、库存和上线时间相互制约时，建立共同排期与风险节点，协调区域团队按市场完成活动交付。

**适配岗位**：Marketing Operations、Campaign Operations

**可迁移价值**：让多个团队在共享资源和不同本地要求下保持交付节奏。

**证据链**：三个市场共用设计和供应资源 → 建立跨团队排期、素材状态与风险清单 → 协调四个职能完成本地化确认 → 三个市场均按计划上线。

### 积木 C｜经营数据决策闭环（Commercial Data-to-action Loop）

**核心能力**：把 SKU、渠道和活动数据整理成固定复盘视图，定位需要进一步验证的经营问题并推动小范围调整。

**适配岗位**：E-commerce Operations、Growth Operations

**可迁移价值**：将日常报表转化为可讨论、可执行的经营判断。

**证据链**：团队原有数据分散且口径不一 → 建立周度 SKU 与渠道复盘表 → 识别组合装在特定市场的转化差异 → 支持团队决定开展下一轮组合与页面测试。

### 积木组合

**A + B**：Regional Marketing Operations

**B + C**：E-commerce Operations

## Why it changed｜变化依据

- “负责东南亚运营”被拆成了用户信号、交付协调和经营判断三个不同闭环。
- 只把林玮明确主导的反馈归类与排期机制写成 ownership；活动销售结果没有归因给个人。
- `18%` 只描述已确认的退款原因结构变化，不扩写为收入增长或用户满意度提升。
- 海外岗位名称用于解释迁移方向，不能反向证明林玮已经具备所有地区经验或任职条件。
